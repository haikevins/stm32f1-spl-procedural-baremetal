# Example 05: Timer PWM

A layered STM32F103C8T6 Blue Pill example using CMSIS and the STM32F10x
Standard Peripheral Library.

TIM2 Channel 1 generates a 1 kHz hardware PWM waveform on PA0. The
Application updates the duty cycle every 10 ms to make an external LED fade
from off to full brightness and back to off.

## Hardware wiring

Use an external LED. The onboard PC13 LED is not connected to a timer PWM
channel.

```text
Blue Pill PA0 (TIM2_CH1) ---- 330 ohm resistor ---- LED anode
Blue Pill GND ------------------------------------- LED cathode
```

| Resource | Configuration |
|---|---|
| Timer | TIM2 |
| Channel | TIM2_CH1 |
| PWM output pin | PA0, alternate-function push-pull |
| PWM mode | PWM mode 1, active-high |
| PWM frequency | 1 kHz |
| Duty representation | 0..1000 permille |
| Duty update period | 10 ms |
| Duty step | 10 permille |
| Timebase | SysTick at 1 kHz |
| Timer interrupt | Not used |

## Expected behavior

After reset, the external LED repeatedly:

1. fades from 0% to 100% duty in approximately one second;
2. fades from 100% to 0% duty in approximately one second;
3. repeats continuously.

The PWM waveform itself is generated by TIM2 hardware. The CPU only updates
CCR1 when the requested brightness changes.

## Dependency paths

```text
Application
    -> PWM Service
        -> Board PWM
            -> GPIO / RCC / TIM2

Application
    -> Time Service
        -> Board Timebase
            -> SysTick
```

Application code does not include BSP, SPL, CMSIS, or STM32 device headers.

## PWM calculations

With the default 72 MHz TIM2 input clock:

```text
Timer tick     = 72 MHz / 72 = 1 MHz
PWM period     = 1 MHz / 1000 = 1000 timer counts
ARR            = 1000 - 1 = 999
CCR1 at 0%     = 0
CCR1 at 50%    = 500
CCR1 at 100%   = 1000
```

The BSP obtains the APB1 clock from `RCC_GetClocksFreq()` and applies the
STM32F1 timer-clock doubling rule when the APB1 prescaler is greater than
one.

## Why no TIM2 interrupt?

TIM2 automatically drives PA0 after configuration. No interrupt is required
for individual PWM periods. SysTick is used only as a slow software
timebase for changing the duty cycle.

## Idle policy

`system_idle()` uses `__NOP()` rather than `__WFI()`:

```c
void system_idle(void)
{
    __NOP();
}
```

This keeps flashing and debugging reliable with an ST-Link that has no NRST
connection. It does not affect the hardware PWM waveform.

## Build

```bash
make check-layers
make clean
make
```

## Flash

```bash
make flash
```

## Configuration

- PWM frequency and timer tick: `config/board_config.h`
- Fade period and duty step: `config/pwm_config.h`
- PA0/TIM2 pin mapping: `bsp/bluepill/src/board_pins.h`
- Selected SPL modules: `config/modules.mk`

## Selected SPL modules

```text
stm32f10x_gpio.c
stm32f10x_rcc.c
stm32f10x_tim.c
```
